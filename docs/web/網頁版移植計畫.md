# 網頁版移植計畫

把 ReturnFare 從 Godot 4.6 / GDScript 移植成純網頁版（TypeScript）。**玩法與劇情一字不動**——它們住在 `data/`，本來就與引擎無關。

本檔是**移植這件事的實作契約與階段拆分**，供指揮 agent 分工使用。它**不重述遊戲規則**：規則的形狀與為什麼在 `溫泉小鎮企劃.md`，引擎必須做什麼在 `實作規格書.md`，可調數值在 `data/`。本檔只回答「同一條規則，在網頁版由誰、用什麼形狀、怎麼驗」。

最後更新：2026-10-31
狀態：**計畫已立，尚未開工**

派工入口：先讀 [共用契約](共用契約.md)，再讀當階段契約：[W1](W1實作契約.md)、[W2](W2實作契約.md)、[W3](W3實作契約.md)、[W4](W4實作契約.md)、[W5](W5實作契約.md)、[W6](W6實作契約.md)、[W7](W7實作契約.md)。本檔保留全案方向與階段拆分；具體 API、修改邊界、命令與驗收依各 W 契約，不另重寫三份完整遊戲規格書。契約齊備不代表程式已實作或已驗收。

## 一、為什麼轉網頁

決策依據，不是重新辯論的入口。使用者 2026-10-30 已拍板走純網頁版。

| 事實 | 影響 |
|---|---|
| 玩法與劇情全在 `data/` 的 19 份 JSON（405 KB） | 換引擎的內容成本為零 |
| 規則層 7,694 行 GDScript，`core/` 七個檔全是 `RefCounted`，只吃 Dictionary／Array | 幾乎是純邏輯，移植是機械性工作 |
| UI 只有 303 行 `.tscn` ＋ 2,276 行 `.gd`，零美術、零主題、沒設字型 | 現有 UI 是程式員鷹架，本來就要丟 |
| 專案還沒有 Art Bible，美術方向未談 | 正式 UI 本來就還沒開始，轉向的邊際成本接近零 |
| 遊戲是全文字、無隨機、決定論 | WASM canvas 渲染文字是結構性錯配；且決定論讓差分測試可行（見第四節） |

Godot Web Export 路線已評估後不採用，理由：下載量 25–40 MB、文字不可選取、無障礙與 SEO 皆不可行、手機瀏覽器不穩，且專案沒有內嵌字型，web 沒有 OS 字型可遞補。

## 二、階段命名規則

**網頁版一律用 `W` 開頭，和 Godot 版的 `P1`–`P6` 完全分流。**

- 格式：`W<數字>-<大寫字母>`，例：`W3-A`
- 數字＝階段群（一個可交付的垂直切片），字母＝子階段（一張工單的大小）
- **子階段一律一列一個，不得合併。** 沿用 `PROJECT_BRIEF.md > Phase 進度` 的規矩，理由相同：合併之後看不出卡在哪
- 本檔不記各階段狀態；整體進度只住 `PROJECT_BRIEF.md`（加入 W 階段列由 verifier 處理）

`P` 編號**不重用、不改寫**。Godot 版的 P1–P6 是已發生的歷史，`驗證後已知問題.md` 的 K 條目大量引用它們。

### 每個 W 階段群是一個垂直切片

和 Godot 版 P 階段的分層做法不同：**W 階段群同時包含規則層、UI 與對帳**，做完就看得到、點得到。

這是刻意的取捨。Godot 版先把規則層全部做完再碰 UI，工程上安全，但代價是很久看不到東西。網頁版反過來，因為黃金軌跡（第四節）讓分段對帳變得可行——安全性不靠「晚一點驗」，靠「每一段都驗」。

## 四、黃金軌跡差分測試

**這是移植案的整合對帳，不必逐行翻譯整套 Godot 測試。** 關鍵規則仍保留必要的針對性測試；驗證取捨見 [共用契約第四節](共用契約.md#四必要驗證的取捨)。

遊戲是無隨機、決定論的（`PROJECT_BRIEF.md > 專案概述` 的驗證哲學）。同一條走法，Godot 版與 TS 版必須走出一模一樣的狀態序列。

### 機制

1. **W1-B**：Godot 端跑既有的貪心走查，在時段操作結束、推進前及結局流程取樣，產出 `trace-godot.json`；精確取樣位置、格式與正式開局未涵蓋的邊界見 [W1 實作契約第三節](W1實作契約.md#三w1-bgodot-黃金軌跡)
2. **W1-C**：比對器讀兩份 trace，逐筆逐欄位 diff
3. TS 具備可對帳規則後，每個相關 W 階段收尾在 Node 跑同一條走法產 `trace-web.json`，**比對該階段已移植到的範圍必須完全一致**；W1 只驗基線與比對器，W2 先驗資料層，不製造假的遊戲軌跡

### 軌跡能證明什麼

軌跡證明既定走法在取樣點的完整狀態一致，差異可定位到時段與欄位；不證明未走到的選擇分支、拒絕操作、UI 接線，或取樣點之間已被後續操作蓋掉的差異。這些只依各階段實際契約補必要案例，不窮舉極端狀態。日常快速檢查由 Node 測試、型別檢查與軌跡 CLI 負責，不靠人工逐頁點網頁。

### 鐵則

- **Godot 版的測試一條都不刪。** 它是對照組，刪了就沒有基準
- 軌跡欄位要涵蓋 run 層與 meta 層的**全部**可序列化狀態。少記一個欄位＝那個欄位沒有保護
- **字典的迭代順序要固定。** GDScript 的 `Dictionary` 保留插入順序，JS 的 `Map` 也是，但兩邊的插入時機若不同，序列化出來就不同。比對器應對字典鍵排序後再比，避免假陽性；真正的順序相依若存在，要在該階段的工單裡寫明
- 分段對帳只比「該階段已移植的欄位」，未移植欄位列進白名單，白名單隨階段推進逐步清空。**W7-A 的驗收就是白名單為空且全程一致**

## 五、技術選型

| 項目 | 選擇 | 為什麼 |
|---|---|---|
| 語言 | TypeScript | 規則層需要型別；GDScript 的 `Array[String]`／`Dictionary` 有直接對應 |
| 建置 | Vite | 靜態輸出，Cloudflare Pages 直連 |
| UI 框架 | React 18 | 45 天完整 UI 的狀態同步需要；且是 agent 訓練資料最密的選擇，交辦品質比較穩。bundle 約 45 KB gzip，相對 Godot 的 25–40 MB 不構成問題 |
| 規則層與框架的關係 | **規則層是純 TS，不 import React** | 必須能在 Node 下 headless 跑完 45 天產軌跡。UI 透過 subscribe 讀狀態，對應 Godot 的 signal |
| 測試 | Vitest（單元＋軌跡）、Playwright（UI） | Playwright 接 `tests/ui_sim/` 的班；專案已有 `webapp-testing` skill |
| 部署 | Cloudflare Pages | 靜態站、免費無頻寬上限、全球 CDN、接 GitHub 自動部署 |
| 後端 | **無** | 存檔走瀏覽器端。雲端存檔與帳號不在本計畫範圍 |
| 字型 | 內文霞鶩文楷 TC（LXGW WenKai TC）、UI 台北黑體（Taipei Sans TC） | 兩套皆 OFL-1.1 可商用。自託管子集化 woff2，不走 CDN |

### 字型的實作要點

- 全部文字在 `data/`，**可以精確算出用到哪些字**。實測現況不重複漢字 **2,155 個**，子集後約 300–500 KB
- 內容推到 5 倍，不重複字數收斂到約 3,200–3,800（繁中 5,000 字涵蓋 99% 以上）。**字型大小有天花板**，乾脆直接出 5,000 常用字全集（約 1 MB）一次做完
- 工具 `fonttools` 的 `pyftsubset`，輸出 woff2，`font-display: swap`
- **自託管在 Cloudflare 上，不要用 Google Fonts 的 CJK CDN**：切片多、請求多、中國大陸連不到
- OFL 義務：保留 `OFL.txt`、不得單獨販售字型、改作不得沿用保留字型名。**上架前逐套開 OFL.txt 確認**

## 六、目錄結構

**同一個 repo，不另開。** 理由是本專案的單一事實來源原則：`data/` 與五份文件是核心資產，分裂它們的代價遠大於 repo 乾淨。而且軌跡對帳要求兩邊讀同一份 JSON。

```text
ReturnFare/
├── data/                  # 不動。Godot 與 web 共用的單一事實來源
├── scripts/ scenes/       # Godot 版，凍結，只讀
├── tests/                 # Godot 測試保留；W1-B 在此加軌跡產生器
├── web/                   # 新增
│   ├── src/
│   │   ├── core/          # TS 規則層，對應 scripts/core/ ＋ game_state.gd。不得 import React
│   │   ├── ui/            # React 元件
│   │   └── data/          # 型別定義與載入
│   ├── public/
│   │   ├── data/          # build 時從 ../../data 複製，不要跨目錄 import
│   │   └── fonts/         # 子集化 woff2
│   ├── tests/
│   ├── package.json
│   └── vite.config.ts
└── tools/trace/           # 軌跡比對器（W1-C）
```

`.gitignore` 要加：`web/node_modules/`、`web/dist/`。

### 檔案對應

| `scripts/core/effect_apply.gd` | `web/src/core/effect.ts` | W3-B 子集 → W5-B 基礎效果 → W6 專用效果 |
| `scripts/core/data_facts.gd` | `web/src/core/facts.ts` | W2-A |
| `scripts/core/panel_builder.gd` | `web/src/core/panel.ts` | W4-B |
| `scripts/core/indulgence.gd` | `web/src/core/indulgence.ts` | W6-B |

## 七、給 agent 的工單格式

指揮 agent 時，每張工單照這個形狀給。缺任何一段就是工單沒寫完。

```text
【階段】W<N>-<X> <標題>

【必讀】
- docs/web/共用契約.md 與當前 W 階段實作契約對應小節
- 對應的 Godot 來源檔（完整路徑）
- 實作規格書.md 的哪一段（驗收意圖）
- 開發設計方針.md 的哪一段（實作契約）
- data/SCHEMA.md 的哪一小節（如涉及資料欄位）

【可以動的檔】
（白名單，逐檔列出）

【不准動的檔】
- data/ 全部
- scripts/ scenes/ 全部（Godot 版凍結，只讀）
- 根目錄五份文件（溫泉小鎮企劃／實作規格書／開發設計方針／測試指南／待決事項）
- 驗證後已知問題.md、PROJECT_BRIEF.md（verifier 角色所有）

【驗收】
- 本步 gate 的確切命令與預期 exit code
- 有規則軌跡時：checkpoint 前綴與未移植欄位的精確路徑（列出）；W1 不宣稱已有兩引擎對帳
- 單元測試：（具體斷言）
- 關鍵接線的最小變異保真：移除接線或反轉判斷後，對應測試必須轉紅；不擴展極端狀態矩陣

【回報】
- 動過哪些檔
- 測試 exit code 與軌跡對帳結果
- 做不到或繞過的地方
```

### agent 鐵則

沿用 `AGENTS.md > 實作守則`（API 簽名預先核對、長函式變數加後綴、編譯錯誤同 turn 修完、角色分離、驗收對應與變異保真、正式資料端到端必測、拒絕原子性與 fixture 隔離）。網頁版額外三條：

1. **遊戲文字一個字都不准改，也不准自己編。** 全部從 `data/` 取出。UI 介面詞彙（按鈕、標籤）另見 W-02 已定決策
2. **規則層不得 import React。** 必須能在 Node 下 headless 跑完 45 天
3. **實作者不自己勾自己的驗收**（K-101）。跑完只提供證據：exit code、軌跡 diff 輸出、實際數字。打勾與落檔由 verifier 做
