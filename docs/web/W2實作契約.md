# W2 資料層實作契約

建立：2026-10-31。這是實作前契約，不是驗收紀錄。先讀 [共用契約](共用契約.md)；前置為 [W1](W1實作契約.md) 已交付且經指揮者核對。

## 一、交付範圍與派工順序

W2-A 建立資料型別、載入、索引與結構事實；W2-B 移植資料驗證並接 build。順序 A → B，兩步不並行修改 loader。完成後瀏覽器與 Node 讀到同一份正式內容，不建立 GameState、不做玩家 UI。

階段概要的「runtime 不再驗證」只指不在每次玩家開頁時重跑全部內容 lint；讀檔／HTTP／JSON 解析失敗仍須明確失敗，不得回空資料後繼續開遊戲。

## 二、必讀與來源定位

| 來源 | 要讀的範圍 |
|---|---|
| `scripts/data_loader.gd` | 欄位、`load_all()`、`_beat_files()`、`verify_references()`；B 再按下節清單讀對應 lint |
| `scripts/verify_data.gd`、`scripts/autoload/data.gd` | 完整驗證接線、warnings、必要 tuning 鍵及結構一致性檢查 |
| `scripts/core/data_facts.gd` | 完整檔案；結構常數、刻意豁免、日期匹配與卡片 base id |
| 根目錄三份 Phase 文件 | 規格書「〇、架構基線」「十七、資料完整性驗證」與 P1-A、P3-A、P4-A、P5-A；方針與測試指南讀相同 Phase 段落及必要共用前言 |
| `data/SCHEMA.md` | 卡型、卡片、地點、NPC、beats、opening、ending，以及條件／效果與相關巢狀欄位；按標題逐段讀 |

**實際 lint 清單取兩個入口的聯集。** `Data._validate_loader()` 只接部分檢查，不能只搬這個函式便宣稱驗證全數移植。規格書的第 6 項是 schema 文件工作，不是另有一支 lint；編號不是連續可執行函式清單。

## 三、W2-A：型別、載入與索引

### 驗收規格

- 讀取全部正式 JSON，保留 authored 欄位、文字與陣列順序；不以 TS 型別轉換順便刪欄或補造內容。
- root 檔案的容器形狀依現行資料與 `DataLoader`：例如 cards 的 `cards[]`、locations 的 `day[]`／`night[]`、opening 的 `screen`／`opening_choices[]`。保留 Godot 仍支援的 opening／ending 頂層陣列相容讀法，不另做歷史存檔遷移。
- beat 檔名排序後串接各檔 `beats[]`，每個檔內不重排。`loadGameData()` 建索引前須攔截全部七個 ID 集合（cardTypes、cards、locations、npcs、beats、endings、openingChoices）的重複 id，包含跨 beat 檔及 day／night 地點陣列的重複；不得讓 Map.set 靜默覆蓋。遇重複 id 或 beat.when 同時含 day 與 day_from，載入直接失敗，不回傳部分 GameData；跨表未知引用由 W2-B 的 `validateData()` 攔截。
- 來源／產物不寫死卡數或 beat 數；CLI 回報當下實際 catalog 數字。

### 型別與 API

由 `web/src/data/types.ts` 定義 `GameData`、內容型別、`Phase`、`CardType`、`Condition`、`Effect` 等。條件用封閉運算子的聯合型別；效果欄位為可選的具體型別，不能以 `any`、全表 `Record<string, unknown>` 取代整份 schema。JSON 的 I/O 邊界可用 `unknown`，解析後才收窄。

尚未有玩法實作的 encounter、delegation、ending 仍須完整保留與描述資料形狀；「可讀取」不代表 W2 已可執行它們。`note` 可留在資料物件，之後 UI view model 不傳給玩家。

```typescript
type ReadText = (relativeDataPath: string) => Promise<string>;
// manifest 路徑相對根目錄 data/，沿用 W1 data_manifest 的 path／sha256 形狀。
function loadGameData(readText: ReadText, manifest: readonly DataFile[]): Promise<GameData>;
```

`GameData` 至少提供 ordered `cards`／`locations`／`npcs`／`beats`／`endings`／`openingChoices` 陣列，以及各自 `ById` 唯讀索引；另含 `tuning`、`relationScale`、`cardTypes`、`openingScreen`。索引用 `ReadonlyMap`；玩法挑選順序讀陣列，不依賴 JS 數字鍵物件順序。重複載入建立新物件，不疊進上一次索引。

`loader.ts` 負責共用解析與建索引；`load-browser.ts` 注入 fetch，`load-node.ts` 注入 Node 檔案讀取。兩邊共用前述 loader，不維護第二份讀取規則。讀檔錯誤帶相對檔名，瀏覽器任一必要檔案失敗就不建立遊戲，不使用空白 fallback 掩蓋。

W1 的同步腳本擴充為額外產生 `web/public/data-manifest.json`，內容 `{ files: DataFile[] }`，path 排序、hash 取來源 bytes。它在 `public/data/` 外，不混進遊戲 JSON，W1 的來源／複製檔案一致性檢查仍成立；加入 ignore，不提交生成檔。瀏覽器先讀 manifest，Node 從同一來源清單載入；Node 可從 repo `data/` 讀原檔，不依賴先開 Vite。

`web/src/core/facts.ts` 移植 DataFacts 的純函式與結構名單。包括章節、四時段、行動時段、純演出／刻意留空／choice-only 名單、已接受的待建卡引用、`beatMatchesTime()`、`cardBaseId()`。固定結構沿來源集中，玩法數值仍從 tuning 取；tuning 的點路徑查詢也在本步提供共用 helper。不把 `tuning.phases_per_day` 當成自由改動時段機的參數。

### 可動檔案

- 新增 `web/src/data/types.ts`、`vocabulary.ts`、`loader.ts`、`load-browser.ts`、`load-node.ts`、`web/src/core/facts.ts`。
- 新增 `web/tests/data.test.ts`、`facts.test.ts`。
- 修改 `web/scripts/sync-data.mjs`、`web/tests/sync-data.test.ts`、`.gitignore`，僅為 manifest 與原同步契約調整。
- 必要時調整 `web/package.json`、`package-lock.json`、`tsconfig.json`、`tsconfig.node.json`；不改 Vite 骨架以外的產品行為。

### 必要驗證

1. Node 載入正式資料，報出 catalog 數字、首末 beat 與檔名排序；與 Godot loader／`verify_data` 的正式輸出核對。測一次重載不累積。
2. 同一測試驗證 `when.day`、日期區間與 phase 陣列，章節界線、純演出名單及 `madness#1` base id。只覆蓋現行語意，不窮舉所有天數組合。
3. 以共用參數化案例確認七個 ID 集合各自的重複 id 均在載入時失敗，尤其 cardTypes 不能等建完 Map 才檢查；另驗 beat.when 同時含 day／day_from，以及讀不到必要檔均明確失敗。使用記憶體 readText 或暫存副本，不改正式資料。
4. HTTP smoke 確認 manifest 與一個 beats JSON 可讀；共用 parser 的正確性由 Node 測，不在瀏覽器重跑全部 loader 測試。`npm test`、`npm run build` 通過。

## 四、W2-B：build-time lint

### 驗收規格與來源清單

新增 `validateData(data): ValidationReport`，報告為 `{ errors: Diagnostic[], warnings: Diagnostic[] }`；diagnostic 至少含穩定 rule id、來源檔／beat 等定位鍵與訊息。**error 擋 build、warning 不擋**，保留既有豁免，不擅自升降嚴重度。正式基線的 warning 要回報實數，不把全零當目標。

registry 使用來源函式名作對照鍵；完整覆蓋以下群組，細節按原函式讀取，不在本檔抄第二份規則：

| 群組 | Godot 來源 |
|---|---|
| 基本結構、引用、tuning | `load_all`、`verify_references`、`Data.REQUIRED_TUNING_KEYS`、行動時段數一致性 |
| 語彙與卡型 | `lint_vocabulary`、`lint_card_types`、`lint_missing_reject_reason` |
| 白天供需、免費槽、殘響 | `lint_choice_rules`／`lint_free_slot_rules` 同源只登錄一次、`lint_action_phases`、`lint_echoes` |
| 縱慾 | `lint_indulgence_integrity`、`lint_indulgence_exits` |
| 夜間 | `lint_night_reachability`、`lint_night_alignment`、`lint_night_locations`、`lint_legacy_night_flags`、`lint_night_once`、`lint_night_location_descs` |
| 委託、遭遇 | `lint_delegations`、`lint_encounters`，包含現有引用及回合可達性檢查 |
| 開局、結局、跨輪 | `lint_endings`、`lint_opening_and_defaults`、`lint_loop_and_festival`、`lint_phase_lifecycle` |

`load_all` 對應的重複 id 與 when 互斥檢查已由 W2-A loader 在建索引前負責，build-time 驗證必先成功載入才進入 `validateData()`；不得假設 validateData 能從已去重的 Map 還原原始重複列。跨表未知引用由 validateData 的 verify_references 對應規則檢查。

語彙鍵表由 W2-A 的 `vocabulary.ts` 匯出，W3～W5 的條件與效果執行器引用同一份。不得把「已知內容欄位」縮成「目前已實作的玩法子集」，以致 W6 正式資料在 W2 就被誤判壞資料。

建置順序改為：同步資料及 manifest → Node lint → TS 型別檢查 → Vite build。提供 `npm run lint:data` 單獨執行；dev 啟動前同樣跑一次 lint，瀏覽器端不重跑。lint 腳本只讀來源，不修 JSON、不自動更新基線；失敗 exit 1，讀取失敗帶檔名且非零退出。

### 可動檔案與必要驗證

- 新增 `web/src/data/validate.ts`、`web/scripts/lint-data.ts`、`web/tests/data-lint.test.ts`。按來源群組確有需要才在 `web/src/data/lint/` 分檔；派工時逐檔列白名單，不先做外掛式框架。
- 修改 `web/package.json`、`package-lock.json`、TS 設定、A 的 loader／vocabulary 與相關測試；只有為接 lint 或避免重複檢查所需的修改。
- 正式資料全套 Node lint 通過，對照 Godot `verify_data.gd` 與 autoload 補充檢查的結果；報告列 registry 已執行的 rule id，不能漏掛某群。
- 只取少量代表案例：未知引用／語彙、已接受的 warning、壞遭遇 next_round、缺夜間 desc。優先沿用現有 fixture 意圖，不為每個內部 helper 新造壞資料矩陣。
- 拔掉 lint 的 build 接線，用上述一個 error fixture 證明檢查會失效；還原後同一案例必擋下。測試將資料根注入測試命令，不修改正式 `data/`；測後完整還原。

## 五、收尾與交接

W2 的驗收是資料與建置一致性，不產假的 `trace-web.json`。指揮者留 A／B 的檔案、API、catalog 實數、rule 清單與各命令 exit code，進 `docs/records/W2實作紀錄.md` 及 `W2_steps/`。Godot 只跑必要的資料驗證，不重跑所有玩法測試。

交 W3 前確認：Node 可以不開瀏覽器讀完整正式資料；UI 不自行 import root `data/`；manifest 是產物；W3 可直接使用型別、facts 與資料查詢。未移植玩法不得靠空物件被標成已實作。
