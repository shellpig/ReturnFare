## 一、交付範圍與派工依賴

W6 完成後，正式資料的夜間、發狂、縱慾、委託、遭遇、結局與跨輪全部接通；同一份規則可從 UI 操作，也可在 Node 跑完 45 天。存檔持久化與正式部署留 [W7](W7實作契約.md)。

五個子階段編號不變，但**先接結局底座，再接可能觸發結局的系統**：

| 施工順序 | 步驟 | 內容 |
|---|---|---|
| 1 | W6-E1 | E 的第一步：結局 resolver、snapshot、模式守衛、逐頁與結算底座 |
| 2 | W6-A | 夜間、發狂卡與倒數、對位；沿用 E1 的 ending request |
| 3 | W6-B | 主動／強制縱慾與時段接線 |
| 4 | W6-C | 委託及隔日上午回報 |
| 5 | W6-D | 遭遇、容量、出口及生命週期接線 |
| 6 | W6-E2 | E 的最後一步：逾期選擇、phase_exit、正常結局及跨輪整合 |

E1／E2 是派工步驟，不新增第六個 W6 子階段。每步都可能改 `state.ts`／`effect.ts`，原則上順序派工，不讓 worker 同時重寫共用檔。**W6-A 第一步就以機制守衛取代 W5 的 D3 evening 日期界線**：檢查整筆命令及目標時段真正會需要哪些系統，只有其中仍未接好的機制才在 mutation 前回 `not_implemented`，不可漏扣代價或跳過內容繼續跑。

各步接好本身系統便移除對應守衛；例如 C 完成後，可信 D17～19 狀態可由 `advancePhase()` 換日回報，D 完成後可從前一時段進 D8／D45 遭遇，不因日期較晚被拒絕。測試不設繞過守衛的開關，使用同一條正式 pipeline。E2 最後確認正式路徑不再碰未完成守衛。**遊戲日期守衛與 Node trace 的前綴截止分開**；trace 的 D3 截止仍到 E2 才擴為全程。

## 三、W6-E1：結局底座先行

### 介面與行為

新增 `web/src/core/ending.ts`，移植純 resolver、stable page ref 組裝與解析。依 endings 資料的有序 rules／lookup 選片段，不在 Game 寫具名伴侶、生計或 NPC 分支。

Game 提供：

```typescript
endingView(): EndingView;
hasSeenEnding(endingId: string): boolean;
revealEndingPage(): MutationResult;
advanceEndingPage(): MutationResult;
skipSeenEnding(): MutationResult;
completeEnding(): MutationResult;
```

`EndingView` 沿 Godot 的 page_text／page_index／page_count／page_revealed／is_last_page／can_skip／can_complete；不把未揭露的其他頁面文字交給 UI。啟動結局由規則內部的 ending request 統一處理，不給 UI 任選 ending 的控制項。

來源與結果只能是現有四組配對：madness_cap→madness BE、ending_effect→inventory BE、d45_coda→正常替換、opening_choice→不上車。先驗配對、資料與 snapshot，再進 ending；同一動作的效果及 bookkeeping 全部 preflight 成功，才提交並凍結結果。不同 ending request 衝突整筆拒絕，不能「先到先贏」。

snapshot、history 欄位與 nullable 矩陣逐項對 `GameState` 最新常數與 parser；不另存已翻譯頁面全文。active ending 保存 stable page refs／進度，history 只存結算結果；knowledge 清單按 cards 順序。首見或重見只看同 ending id 的 history，不以輪數替代。

進 ending 立即封鎖一般放卡、choice、委託、縱慾、夜間進入、對位及時段推進。`completeEnding()` 是唯一收尾：完整驗 ready 與 record → append history → 取得回溯知識 → 增加輪數 → 清 run／active → opening。meta 含白天地點 visited 等既有欄位全保留，run 清除與 W3 開局初始化共用一份定義。重複 complete 不可多寫一次 history。

E1 建立這些完整規則與可重用結局 UI；正常 D45 的觸發接線、D29 代付與全程整合在 E2 補。W3 已鎖定的不上車解鎖流程在此接通，不能建立假小鎮 run。

### UI、白名單與必要驗證

- 新增 `web/src/core/ending.ts`、`web/src/ui/EndingPanel.tsx`、`web/tests/ending.test.ts`、`web/tests/ui/ending.spec.ts`。
- 修改 state／state-types／effect／condition／OpeningPanel／GameShell／strings／styles、必要測試支援。純 resolver 不 import React。
- 逐字顯示只在 UI；一次滑鼠／鍵盤輸入只能補完當頁或翻頁其中之一，末頁揭露才可結算。首見不提供跳過，重見按 `repeat.skip_to`；不能自行跳到最後一頁冒充資料指定落點。畫面拆換後取消舊逐字計時器，不能在新輪觸發舊 callback。

## 四、W6-A：夜間、發狂錶與對位

### API 與資料流

先替換上述日期守衛，再擴充 W3 的 `night.ts`、cards／panel，新增 `web/src/core/madness.ts`；Game 接：

```typescript
nightLocationSummary(locationId: string): NightLocationSummary;
resolvedNightContent(locationId: string): ResolvedNightContent;
enterNightLocation(locationId: string): MutationResult;
alignmentOffer(dayLocationId: string): AlignmentOffer;
confirmNightAlignment(dayLocationId: string): AlignmentResult;
```

`NightLocationSummary` 至少含 display_name、desc、status_text、can_enter、reason_code／text、warning、teaser_only；沿 T-04 只顯示外部可觀察的簡介。`ResolvedNightContent` 含 primary／addons 的既定有序內容，不另讓睡覺、面板與合法性各掃一次 when。

候選產生與有狀態解析分兩層：當日定日優先，否則取章節內最接近變體；condition 不成立可按來源退回下一候選，requires 不成立仍是選中的 LOCKED 內容；addons 保序並列。無內容不是假 beat。前兩夜 fixed 沿 W3 原入口擴充，meta_once、repeat_each_run、強制到訪與 D3 引導等按資料處理，不寫每日特例表。

主動進入先驗 mode／時段／遭遇／超載／地點與門檻／當夜已選或已睡，再提交 chosen／meta seen，終身首次才收 marker cost。先記 seen 再檢查 cap：撞 BE 仍保留到訪；不得在 ending 後繼續播原面板。一般重訪免 marker cost，不代表免去 beat 自己的效果。風險 warning 用純 preflight，不實際發卡。

所有發狂來源共用發卡 primitive，instance id 與時計一致；每日進 morning 才 tick，歸零 clamp、不重複入 forced_pending，產生當夜不倒數。cap 依手牌實例數判斷；批次效果先完整 preflight，最後只派一個 ending request。A 建立 `madness` 效果及直接 gain madness 的正式支援，B 再接歸零後的強制縱慾；B 未接前，會需要強制結算的推進不得半途改狀態。

睡覺由 `advancePhase()` 吸收：有旅館內容時先播並停拍，第二次才換日；已選地點不再睡一次。UI 按鈕三態沿原詞彙，詳情本身不收費、不消耗今晚。對位在正確白天地點免費確認，共用 knowledge；matched 純衍生，不新增序列化集合或在地圖曝光尚未到訪的夜間分區。

## 七、W6-D：遭遇

新增 `web/src/core/encounter.ts` 作純回合查詢／候選／view；Game 持有 active_encounter，提供：

```typescript
encounterView(): EncounterView;
acknowledgeEncounterIntro(): MutationResult;
respondToEncounter(cardId: string): MutationResult;
discardInEncounter(cardId: string): MutationResult;
escapeEncounter(cardIds: readonly string[]): MutationResult;
```

startEncounter 為規則生命週期使用，非玩家任意選 beat 的 API。新時段的 due fixed encounter 在規則層建立；D8 night 的 repeat_each_run／charge_first_visit 沿資料，D45 afternoon 入口同樣從 transition 接，不靠 UI 知道日期才呼叫 start。

intro → round、佔格、正答／錯答、discard／escape、after_finish 都按資料走。response 匹配沿來源的 card／base id 規則，不拿普通 slot 的 type accepts 規則直接套用。attempted 依 base card 記，hand 與 knowledge 都須過濾；discardable 讀卡片欄位。發狂卡不作回應或逃離支付；知識不佔容量，也不變成可丟棄卡。

佔位是 blocked_slots，不是假卡；成本讀現行資料，D45 已接受的零成本不得被移植時擅改成正數。滿格與無合法解按來源進 failure，不開備用區。discard 能減手牌壓力，但不回退 round／blocked_slots；同一 base 本場已試不得重試。遭遇出口效果、支付卡與 active 狀態同交易，ending 啟動後不再自動 advance；正常 after_finish 的推進走同一個 Game pipeline。

- 新增 `web/src/ui/EncounterPanel.tsx`、`web/tests/encounter.test.ts`、`web/tests/ui/encounter.spec.ts`；修改 state／effect／cards／panel／GameShell／CardDetail、greedy helper。
- Node 以正式 D8 及 D45 各從前一時段 `advancePhase()` 進遭遇，D8 包含入夜 fixed 接線；驗 intro、合法回應及出口。另用同一正式定義的可信狀態驗一次錯答、discard、escape、容量失敗，不做所有回合路徑排列。
- 重複 base、未持有卡、不可丟卡等關鍵拒絕以代表案例驗 serialize 不變。效果一次性用 gain 數量／relation／blocked_slots 的可分辨斷言。

## 八、W6-E2：出口規則、全程與跨輪收尾

沿現行 `advance_phase()` 的固定順序整合：mode → active encounter → night 停拍 → 逾期 choice default preflight → phase_exit → 目標時段／ending 資料驗證 → commit。內部可拆 helper，但只有一條 transition 真值；D45 無 night，不建立 D46，也不復活 legacy end_run。
