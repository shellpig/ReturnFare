# W7 收尾與上線實作契約

建立：2026-10-31。實作前契約；先讀 [共用契約](共用契約.md)、[W6](W6實作契約.md)。前置是正式規則／UI 已接通且 Node 能完成全程。W7 不補新劇情、第二輪差異包、Steam 包裝、帳號、雲端存檔或 i18n。

## 一、範圍、順序與仍待決的邊界

W7-A 全程對帳 → W7-B 本機存檔 → W7-C 字型定稿 → W7-D 部署。B／C 都會影響最終成品，D 前須在最後版本確認既有證據仍適用，必要時補受影響檢查，不無條件重跑所有歷史測試。

存檔採最小可用方案：**localStorage，一份自動檔、一份手動檔**，不上 IndexedDB、多槽位管理、匯入／匯出或雲端同步。這兩份是固定用途，不是可調玩法數值。web envelope 具有自己的版本，payload 沿 GameSnapshot 的 flow／run／meta；不提供 Godot 存檔轉換，亦不替待決 W-05 承諾永久跨引擎相容。

W-02 介面詞彙、W-03 美術定位、W-06 Godot 人工驗收歸屬，按 `待決事項.md` 第六節的單一來源處理。它們不阻止本機收尾，但對外版本是 prototype 還是正式版、哪些呈現仍屬暫定，須在部署交付中明確，不能替使用者宣稱正式商用品質。未指定雲端帳號／目標時，先完成可檢查的本機產物，不亂建服務。

## 二、W7-A：全程對帳與候選版證據

### 驗收與命令

沿 W1 的格式、W6 的同一個 Node runner，比完整 greedy-v1，不帶 `--scope`，也不把開局相簿／電話混入 Godot helper 初態。包含 179 個 phase_end 與實際結局頁步驟，最後回 opening；總筆數依正式頁數，不硬寫估值。

```powershell
# cwd: web/
npm ci
npm test
npm run build
npm run trace:web -- --output ../_qa/web/trace-web.json
npm run trace:compare -- ../tools/trace/baselines/greedy-godot.json ../_qa/web/trace-web.json
npm run test:ui
```

W7-A 只跑目前必要 UI 集，不再擴張多瀏覽器、全狀態畫面或極端資料測試。開局、夜間、委託、遭遇、結局與重新開輪的代表接線已在 W3～W6 定義，這裡確認整合後仍過。完整 trace 比較不得零欄位、忽略整區、丟掉陣列順序或少一段 ending。

expected 只由 Godot 明示生成。manifest 不一致先確認資料變更來源；若確有基線更新需要，按共用契約重新生成並 review 差異，不能拿 web 結果覆蓋。正常接手不必每次再跑 Godot：已記來源 revision／manifest 的有效基線即可作對照。

本步主要交證據。若對帳發現問題，只修改定位到的 `web/src/core/`／`ui/` 檔及對應測試，派工先逐檔列明；不得授予整個 repo 任意重構白名單。W1 比對器或基線有問題時另列明具體原因與修改範圍，不暗改測試口徑。

`_qa/web/` 保存 actual trace／差異 log／必要 UI 產物；指揮者在 `docs/records/W7實作紀錄.md`／`W7_steps/` 記來源 commit、manifest、實際 checkpoint／欄位數、exit code、未驗證項目。verifier 文件另依角色更新；有人工體感待做就明列，不把它標為已過。

## 三、W7-B：本機存讀與正常啟動

### 資料形狀與責任

讀根目錄規格書「十六、迴圈、繼承與存檔分層」、P5-B／D／F 的 snapshot 與原子還原契約；方針、指南讀同段。核對最新 `game_state.gd` 的 `deserialize()` 與 `_parse_flow_block`、ending result／snapshot／history、day visited／persistent parser。Godot 的舊 checkpoint 相容分支不是 web 必做功能；web 第一版不發明 v0 或猜遷移。

```typescript
type SaveEnvelope = {
  format: 'returnfare-web';
  version: 1;
  saved_at: string;          // UTC ISO 字串，只供存檔 UI 顯示
  state: GameSnapshot;
};
type SaveSlot = 'auto' | 'manual';
```

localStorage key 固定為 `returnfare.save.auto`／`returnfare.save.manual`，版本放 envelope，不因升版換 key 讓舊檔看似消失。saved_at 不進 GameSnapshot／trace，Node 測試注入時間來源，不把真時鐘造成的差異當玩法差異。

新增純 codec `encodeSave(snapshot, savedAt): string`、`decodeSave(text,data): SaveDecodeResult`，後者成功才返回可信 GameSnapshot，失敗帶可辨識的 code；不得把 JSON.parse 後的物件直接傳給 W3 僅接受可信資料的 initialState。檢查目前版號、必要欄位、型別／數字範圍、mode／active 關係、卡片與 beat／slot 引用、ending refs／頁碼、history nullable 矩陣及已存在的 run／meta 集合語意。實作以實際可還原狀態為準，不為理論上的任意物件建通用驗證框架。

validation／decode 是純 TS，不碰 localStorage、不改目前 Game。storage adapter 才包 getItem／setItem 的 try/catch 與 key，UI controller 負責成功後替換 Game instance、解除舊訂閱與 timer。不要先清目前遊戲再嘗試載入；壞檔、未支援版本、寫入失敗，都保留現有遊戲與既有可讀檔，不自動刪檔或偷偷建新局覆蓋。

### 儲存時點與還原行為

- 自動檔在成功的完整遊戲命令後更新，保存同一筆提交完成的 snapshot；不是逐字動畫／每幀重寫。拒絕與單純 hover／預覽不寫檔。結局完成後要記到 opening，新輪開始後再更新新 run；不能在頁面剛啟動、尚未讓玩家選繼續時用空新局覆蓋舊自動檔。
- 手動檔由明示「存檔」操作覆寫；有舊手動檔時先確認，取消不動任何狀態。使用者可從「讀取」載入手動檔；自動檔供啟動時「繼續」。這些介面詞彙先集中沿既有 strings 模組，依 W-02 定案調整，不新增遊戲文本。
- 不保存未確認選項、滑鼠位置、開著的詳情與動畫游標。run 讀回當前時段主畫面，必要的規則演出按已記錄的 beats_entered／seen 冪等處理，不能重發卡、再收夜間首次費或再結一次委託。active encounter 依已存 stage／round／blocked_slots 還原，不再 start／charge 一次。
- ending 依 stable refs／page_index／page_revealed／ready 還原同一頁；不上車與 opening 維持各自 mode。不得讀到 ending 就直接 complete 或重新建立一次 snapshot。
- 儲存不可用時顯示失敗且允許記憶體中的遊戲繼續，不顯示假成功。換網域／瀏覽器不保證帶著本機檔，UI 說明只需指出「儲存在此瀏覽器」，不加帳號暗示。多人多分頁同時覆寫合併不在本階段範圍。

### 白名單與必要驗證

- 新增 `web/src/save/codec.ts`、`storage.ts`、`types.ts`、`web/src/ui/SavePanel.tsx`、`web/tests/save.test.ts`、`web/tests/ui/save.spec.ts`。
- 修改 App／GameShell／use-game／strings、必要 snapshot 型別與 core 的純還原驗證；不在 core import window。若需拆 parser，只新增對應 save 模組，勿重做 GameState。
- Node 用正式可達的 run、active encounter、ending、opening 各一個快照驗 roundtrip；再從載入的 pending report／madness 狀態推進一次，證明後續行為與未中斷實例相同。優先共用 W6 fixture，不新建大量狀態矩陣。
- 只測代表失敗：不可解析 JSON、較新未支援版號、非法 ending ref／history 一例，以及 adapter 寫入失敗；現有狀態及舊檔不變。無須模糊測試、巨大 history 或所有欄位破壞排列。
- Playwright 一條正常存檔→關閉目前頁面→同 context 重開→繼續／讀取，確認日／時段、持有與已耗行動恢復；另驗 ending 頁碼還原，Node 已驗的全欄位不用逐一截圖。
- 最小變異移除 decode 成功才替換 Game 的 gate 或 autosave 接線擇一，對應測試必紅；還原後通過。測試使用隔離 context／記憶體 storage，不能清使用者真實瀏覽器的存檔。

## 四、W7-C：字型自託管與子集化

沿 W3 的兩套字型與已核對來源／授權，處理大小與字形完整性，不更換美術方向。語料以正式 data JSON 的字串，加上 strings 模組中實際 UI 詞彙與必要數字／標點產生；不只掃故事正文而漏掉卡名、按鈕、知識與結局。來源字元集合是必要下限，不以一份固定常用字表取代，避免姓名與少見字缺字。

建立可重跑的語料收集與 subset 命令；原字型及語料中間檔放 repo 外或 `_qa/fonts/`，repo 保留部署用 woff2、既有授權原文與生成腳本。需要 fonttools 時依 AGENTS 建專案 `.venv`，用 `.\.venv\Scripts\python.exe`；不得用系統 Python。工具依賴記於 `tools/fonts/requirements.txt`，實作時固定實際可用版本。

W3 原檔名可維持 CSS 引用，若授權或保留名稱要求不同則同步檔名／font-family 與引用；不能自行刪授權或假設改名規則。`font-display:swap`，不加 CDN。子集化失敗保留上一份可用字型，不能先刪成品再留下缺檔。

- 可新增 `web/scripts/collect-font-text.ts`、`tools/fonts/subset_fonts.py`、`requirements.txt`，修改 `web/public/fonts/` 的成品／授權及 styles／package 必要入口。
- 逐套用 cmap 核對所需字元沒有缺漏，回報前後實際大小。這是必要完整性檢查，不先追求某個估計 KB 指標。
- Node／build 不受影響；以一個正式長文與罕見角色字的 UI 畫面確認載入及換行，檢查 HTTP 字型資源成功。不要建立所有頁面的視覺差分庫。
- 若 W-02 之後改 UI 詞彙或內容更新，重跑同一命令再核對字元，不能手工補一份字表而失去單一來源。

## 五、W7-D：Cloudflare Pages 候選版與部署

### 建置契約

沿總計畫的靜態 Pages，不新增後端、Functions、service worker 或離線同步。建議 Cloudflare 的 repo root 留在專案根，build command 為 `npm --prefix web ci && npm --prefix web run build`，output directory 為 `web/dist`；如此 root `data/` 與 web 腳本都在同一次 checkout 下。這是本 repo 的命令組合，對照 [Cloudflare build configuration](https://developers.cloudflare.com/pages/configuration/build-configuration/) 的 root／command／output 設定；平台 React Vite 標準輸出為 dist。

Node 版本與本機 lockfile／實作工具鏈一致，實作時核對平台可選版本，不依賴它的隱含預設。必須在無預先生成 public/data 的乾淨 checkout 成功建置；不能讓本機殘留產物替雲端補檔。

正式入口保持 `/`，不為上線另引進 Router。若未來真的新增客戶端路由，再依 [Pages SPA serving](https://developers.cloudflare.com/pages/configuration/serving-pages/) 處理 fallback；本次不先加萬用 rewrite，避免把錯誤 JSON／字型路徑回成 HTML 當成功。沿平台預設快取，不新增永久快取可變 data manifest 的規則；每次候選版驗證實際取得的 manifest 與該 build 一致。

只部署 Vite build 產物。**Vite 會原樣複製 public/**，因此既有 `web/public/art/`、fonts 除成品與授權不得混入 raw／prompt／臨時資料。檢查 dist 沒有 UI fixture host、QA 注入入口、Godot 腳本、docs、trace baseline 或本機存檔；不要因為 repo 同放 Godot 就把根目錄當靜態資產目錄上傳。

### 本機候選版與實際部署

- 可修改 `web/package.json` 增加 `preview`（Vite preview），及已定位的 build／Vite 設定；只有確有用途才新增平台設定檔。Pages Git 設定記在實作紀錄，不為了本機 smoke 增加雲端 CLI 依賴。
- 本機先 `npm run build`，以 `npm run preview -- --host 127.0.0.1` 啟動真正 dist，驗 HTML、manifest、JSON、圖片與字型；再用專用 Chromium 跑一條開局到可操作畫面的 smoke，結束關服務與瀏覽器。不能只測 dev server 宣稱產物可部署。
- 既有 clone 不能算乾淨建置證據；可用獨立 checkout 或 CI build，不清使用者 workspace／public 素材來製造「乾淨」。來源 commit、Node／npm 版本、build command 與產物大小寫進交接。
- 本次撰寫契約不授權雲端操作。未來任務若已授權 W7-D 部署且帳號、Pages 專案與 production branch 明確，照指定目標執行；缺目標才詢問，不自行選帳號／域名。先完成可審閱產物與檢查，不把「先問要不要開始做」當最後步驟。
- Git 自動部署設定須明確區分 preview／production，避免任何 worker push 都成公開上線。正式切換按使用者指定版本，保留上一個可回退部署 id；不擅自購買網域、改 DNS 或升級付費方案。

### 必要線上驗證與交付

目標 URL 上確認同版本 manifest／JSON／字型／圖可讀，跑一條開局 smoke，另在該 origin 做一次隔離的存讀測試。不要把 preview origin 的 localStorage 會帶去 production 當驗收條件；本機檔與 origin 的限制在 UI 已說明。

平台 build／網路失敗就回報真實錯誤與最後成功部署，不把 HTTP 200 的 SPA HTML 當成 JSON 成功，也不以本機全綠代替線上證據。Chromium 不可用或驗收失敗，按共用契約停該瀏覽器驗收，保留已完成的 CLI／HTTP 證據與未驗項目，不回退 Edge。

交付 URL、commit／deployment id、實際命令與 exit code、manifest、必要 UI／存讀證據、字型／素材交付清單及已知限制。未獲部署目標或授權時，交本機候選版與剩餘條件，不把 W7-D 標完成。
