## 一、先讀這一節：知識卡跨輪保留

知識卡與其他卡最大的差別有兩個，整張表的讀法都跟著它們變。

**① 不佔手牌格。** `slotless: true`，進的是 `GameState.knowledge`（一個 Set），不進 `hand`。所以知識卡永遠不會把手牌撐爆，也不出現在手牌格線裡（P1-H 把它移到計數右邊的獨立入口）。

**② 跨輪保留。** `knowledge` 住 meta 層，`end_run()` 清掉 `hand` / `flags` / `switches` / `relations` / `beats_entered`，**唯獨不清 `knowledge`**。加上 `gain_card()` 對知識是冪等的（已有就 return），於是：

| | 第一輪 | 第二輪以後 |
|---|---|---|
| 取得 | 要照下表的條件走到那一格 | **已經有了**，同一格再拿是 no-op |
| 使用 | 要先取得才開得了門檻 | **開局就成立**，不必重做調查 |

`n_ahong_7` 的 `note` 把這件事寫得最清楚：「三張對位知識卡已經在第四、五、六級發完，而它們**跨輪繼承**——第二輪玩家第 43 夜可以直接站到這裡。」

> **這代表知識卡是目前唯一的跨輪進度載體。** 第二輪玩家不是「記得」線索，是**真的持有**它們，門檻直接開。設計時要記得：任何掛 `has_knowledge` 的內容，第二輪都會提早出現。

| `d19_pm_upstream` | D19 下午 · 上游源頭 | **beat 級 `requires`** — 不成立整個 beat 灰掉 |
| `d43_morning_dig` | D43 上午 · 納骨塔，槽 `recount` | **槽級 `requires`** — 不成立該槽灰掉 |
| `d43_conclusion` | D43 下午 · 山泉閣 | **beat 級 `condition`**，九項裡湊滿三項才出現 |

> ⚠️ `d19_pm_upstream` 的 `note` 自己記著一個落差：「`requires` 暫時掛在 `k_forty_something` 上，但故事線寫的門檻是『登山隊給的路線（第一章第 7-9 天）＋第 7 夜看過』。第一章沒有替登山隊路線建卡，也沒有『看過某個夜間標記』的條件語彙——這一條要回頭補。」**這是資料層的既知代用，不是本檔的判斷。**

九項裡只有兩項是知識卡（`k_forty_something`、`k_twenty_years_ago`），其餘七項是佔格情報卡。**知識卡跨輪、情報卡不跨輪**，所以第二輪玩家開局就先湊到兩項，只要再拿一張情報卡就開得了 `d43_conclusion`。

這是全作唯一「知識卡開地點」的用法。四級接力，每一級的門檻是上一級給的知識：

### 3.3 D45 的兩組：知識卡在結局當「兌現」用

第 45 天是全作唯一「把佔格情報卡換成知識卡」的地方，兩組形狀不同。

**理論卡三選（`d45_encounter`，D45 下午）**：三個槽各收一張推論卡，放下去 `lose` 那張卡、`gain` 對應知識。

| 槽 | 吃掉 | 換到 |
|---|---|---|
| `play_theory_exchange` | `inf_health_disappearance` | `k_health_from_disappearance` |
| `play_theory_jinghe` | `inf_jinghe_does_it` | `k_jinghe_not_entrance` |
| `play_theory_hotspring` | `inf_hotspring_kills` | `k_not_side_effect` |

> 全作只有這三張佔格卡會被 `lose`，其餘 39 張拿到就一直在手上。

**名冊升級（`d45_then`，D45 傍晚）**：進場先給 `k_not_today`，之後放 `info_registry` 進 `compare_registry`，`lose: k_not_today` ＋ `gain: k_already_on_list`。等於一次知識卡的**升級**，從「不是今天才輪到我」變成「我在回來之前，就已經在名單上」。

> **升級是單向的（2026-08-16 修）。** 原本有一個跨輪缺陷：`k_not_today` 是第一輪唯一會被 `lose` 的知識卡，而 `beats_entered` 每輪清空、`knowledge` 不清，於是第二輪 `d45_then` 進場又 `gain` 一次 `k_not_today`，玩家同時持有升級前與升級後兩張。
>
> 修法是給 `on_enter` 的發卡加守衛：
>
> ```json
> "gain": [
>   { "card": "k_not_today", "if": { "not": { "has_knowledge": "k_already_on_list" } } }
> ]
> ```
>
> 這是新的通用語彙（`data/SCHEMA.md > 帶條件的卡片項目`），不是為這一格寫的特例。**守衛下在單張卡上，不是整個效果塊**——同一個 `on_enter` 的 `flag: loop1_end` 照常寫入。**之後每做一組升級型比對，都要在發舊版的地方加上同樣的守衛。**

1. **內容缺口**——後面本來要有門檻用它們，還沒寫。

有兩件事值得單獨拿出來想：

- **`k_already_on_list` 比較可疑。** 卡面寫「我在回來之前，就已經在名單上」，聽起來像迴圈敘事的關鍵；它沒有任何消費者，而且跨輪保留。如果第二輪要有「你已經知道自己在名單上」的分歧，掛的就是它。

## 五、引擎現況：阿宏鏈三張目前拿不到

`k_ahong_point_1` / `_2` / `_3` 在資料上完整（給的地方、用的地方都在），但**現在玩不到**。

原因在 `scripts/core/panel_builder.gd` 的 `build()`：夜間分支對任何 `madness_cost > 0` 的地點一律回一個 LOCKED stub 面板，帶假 beat id、空 `slots`。四個阿宏地點的 `madness_cost` 都是 1，所以：

1. 地點**列得出來**（`available_locations()` 只看 `layer` 與 `earliest_night`）。
2. 玩家點下去，P2-A 的 `open_night_marker()` **會照收發狂卡**。
3. 但面板是 LOCKED stub，真正的 beat（`n_ahong_4_ch2` 等）**沒有被演出**，於是它的 `on_enter.gain` 從來不執行。

**結果是：進去要付發狂卡，卻拿不到知識卡。** 這條路要等 **P3 夜間層真值化**才會通。相關的已知條目是 `驗證後已知問題.md > K-34`（夜間分支不檢查地點級 `requires`）與 `K-35`（回傳資料裡不存在的假 beat id），兩條都排在 P3。

> 連帶影響：`n_ahong_5` / `_6` / `_7` 的門檻查的正是這三張知識，所以**整條阿宏鏈在 P3 之前都是死的**。`§3.2` 那張表描述的是資料的意圖，不是現在跑得出來的行為。
>
> 也就是說，實際「拿得到而且有人用」的知識卡，現在只有 `k_forty_something` 與 `k_twenty_years_ago` 兩張。

## 附：本檔欄位為什麼是這幾個

除了指定的 id / 中文名稱 / 哪邊取得 / 誰在用，另外補了四欄，理由各自不同：

| 欄位 | 為什麼要有 |
|---|---|
| **章** | 知識卡的取得散在三章，排序看得出調查線的節奏 |
| **取得前置** | 11 張裡有 10 張帶條件（要先有某張卡、某個旗標、或某張知識），只寫「哪邊取得」會漏掉一半資訊。真正無條件的只有 `k_twenty_years_ago` 一張 |
| **引擎現況** | 資料完整不等於玩得到——阿宏鏈三張現在拿不到，不標的話這份表會誤導 |
| **卡面文字** | 內容期要改文字，而判斷「這張要不要留」需要看得到它寫什麼 |

**沒有放進來的**：`type`（11 張全是 `knowledge`，整欄同值）、`slotless`（同上，恆為 `true`）、`unique`（知識本來就冪等）。同值欄位放進表只會佔寬度。
